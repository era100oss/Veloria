Я сейчас объясню, как этот плагин работает **внутри** — по шагам, просто и понятно, но с полным раскрытием механизма (на основе именно того кода, который ты прислал).

### Общая схема работы

Всё крутится вокруг одной большой функции `$output(data, opts)`, которую Perchance автоматически вызывает, когда ты пишешь `[image(...)]`.

Эта функция делает три разных вещи в зависимости от того, что ты передал:

1. **Генерация изображения** (основной режим)  
2. **Отображение галереи** (если передан объект с `gallery = true`)  
3. **Обработка сообщений от сервера** (лайки, сохранения, обновление высоты галереи и т.д.)

### 1. Подготовка (выполняется один раз при загрузке генератора)

При первом вызове плагин создаёт глобальный объект `window.___textToImagePluginData98420274` и вешает **общий обработчик сообщений** `window.addEventListener("message", ...)`.

Этот обработчик ловит сообщения от iframe'ов (которые приходят с сервера perchance.org) и реагирует на:
- Открытие галереи по сигналу от сердечка
- Обновление высоты галереи (adaptiveHeight)
- Сохранение изображения (обновляет все галереи на странице)
- Клик по кастомным кнопкам в галерее

### 2. Режим галереи (если data.gallery = true)

- Устанавливает contentFilter = "pg13" по умолчанию (даже если ты не указал)
- Собирает все параметры (sort, timeRange, bannedUsers, bannedPromptPhrases и т.д.)
- Генерирует уникальный ID галереи
- Создаёт URL для iframe: `https://image-generation.perchance.org/gallery?...`
- Вставляет или обновляет `<iframe class="text-to-image-plugin-gallery">` на странице
- Сохраняет URL галереи в `window.lastUsedTextToImagePluginGalleryIframeUrl` (для всплывающих галерей по клику на сердечко)

### 3. Основной режим — генерация изображения

Это самый большой и сложный блок.

#### Шаг 1: Парсинг входных данных
- Если ты передал просто строку → она становится `prompt`
- Если передал объект → берёт из него prompt, seed, resolution и т.д.
- Специальный парсинг промпта: ищет конструкции вроде `(resolution:::512x768)`, `(seed:::12345)`, `(negativePrompt:::blurry, low quality)` и вытаскивает их в отдельные параметры
- Применяет значения по умолчанию (resolution = "512x512", guidanceScale = 7, width/height ~300px и т.д.)

#### Шаг 2: Проверки и исправления
- Проверяет, что guidanceScale — целое число от 1 до 30
- Проверяет, что resolution — одна из разрешённых (512x512, 768x768, 512x768, 768x512)
- Если указан `size` — работает только с квадратными разрешениями
- Рассчитывает CSS для width/height с учётом aspect-ratio

#### Шаг 3: Создание iframe для генерации
- Генерирует случайный `privateIframeId`
- Создаёт URL с хэшем: `https://image-generation.perchance.org/embed#data=...`
  В хэш запакованы все параметры: prompt, seed, resolution, negativePrompt, saveTitle и т.д.
- Возвращает HTML-код iframe с классом `text-to-image-plugin-image-iframe` и `data-src` (реальный src подгружается только когда элемент виден на экране — lazy loading через IntersectionObserver)

#### Шаг 4: Ожидание готовности изображения
- Вешает обработчик сообщений специально для этого iframe
- Когда сервер присылает сообщение `type: 'finished'` с `dataUrl` (готовое изображение):
  - Если включён `removeBackground` → запускает локальную нейросеть (Hugging Face transformers) для удаления фона
  - Создаёт canvas из dataUrl
  - Сохраняет всё в объект outputData: dataUrl, canvas, inputs (включая реально использованный seed), iframe
  - Если iframe всё ещё в DOM → прикрепляет к нему свойство `textToImagePluginOutput`
  - Если был параметр `onFinish` → вызывает твою функцию
  - Разрешает Promise (await image(...) теперь возвращает готовый объект)

#### Шаг 5: Автоматическая генерация без вставки в DOM
Если ты использовал `await image(...)`, но не добавил iframe в HTML вручную — плагин через 150 мс сам создаст скрытый iframe (opacity:0, position:fixed), чтобы генерация всё равно произошла.

### Особенности и хитрости внутри кода

- **Lazy loading**: все iframe'ы с классом `text-to-image-plugin-image-iframe` получают IntersectionObserver — картинки начинают генерироваться только когда прокрутишь до них.
- **removeBackground**: работает полностью на клиенте (загружает модель ~100 МБ один раз, потом быстро удаляет фон).
- **referenceImage**: поддерживается, но с ограничениями (только определённые URL или blob).
- **Галерея и сохранения**: вся коммуникация идёт через postMessage между твоей страницей и серверными iframe'ами.
- **Безопасность**: все origin проверяются на `https://image-generation.perchance.org`

### Итог

Плагин — это умная обёртка, которая:
1. Принимает твои настройки
2. Формирует защищённый запрос на сервер Perchance
3. Вставляет iframe, который общается с сервером
4. По готовности отдаёт тебе либо просто картинку (в [image()]), либо полный объект с canvas и dataUrl (при await)

Всё остальное (галерея, модерация, кастомные кнопки) — это дополнительные режимы той же функции.
